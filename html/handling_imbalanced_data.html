The Problem

Imbalanced Datasets

In real-world ML engineering (like fraud detection or disease diagnosis), the data is rarely 50/50. One class heavily outweighs the other.

If a dataset has 95% legitimate transactions and 5% fraud, a naive model can achieve 95% accuracy simply by guessing "legitimate" every time. Standard metrics mask the fact that the model learned nothing about the minority class.

The Accuracy Trap:

$$Accuracy = \frac{\text{Correct Predictions}}{\text{Total Predictions}}$$
Technique 1

Random Undersampling

Concept: We randomly delete examples from the majority class until it matches the size of the minority class.

Pros

Perfectly balances the dataset and drastically speeds up model training times.

Cons

We throw away a massive amount of potentially valuable data and patterns from the majority class.

Technique 2

Random Oversampling

Concept: We randomly duplicate existing examples from the minority class until it matches the size of the majority class.

Pros

No information is lost from the majority class.

Cons

The model sees the exact same minority data points repeatedly, leading to a high risk of overfitting (memorizing the data instead of learning general patterns).

Technique 3

SMOTE

Synthetic Minority Over-sampling Technique creates new, artificial data points instead of just copying old ones.

It works by selecting a minority point, finding its nearest minority neighbors, and generating synthetic points (the green dots) randomly along the line segments connecting them.

This expands the decision boundary of the minority class safely, reducing the risk of overfitting compared to simple duplication.

Algorithmic Approach

Class Weights

Instead of generating new data, we change the algorithm's math. We assign a higher "penalty" (weight) for misclassifying the minority class during training.

Standard Scikit-Learn Weight Equation:

$$W_{j} = \frac{n\_samples}{n\_classes \times n\_samples_{j}}$$

Example (100 total, 2 classes, 10 minority):

$W_{minority} = \frac{100}{2 \times 10} = 5.0$
$W_{majority} = \frac{100}{2 \times 90} \approx 0.55$

The model now cares ~9x more about getting the minority points right!

Production Practice

Evaluation Metrics

Because Accuracy is flawed here, ML Engineers use Precision, Recall, and the F1-Score to evaluate models on imbalanced data.

Precision (Quality of positive predictions)

$$Precision = \frac{True\_Positives}{True\_Positives + False\_Positives}$$

Recall (Quantity of actual positives found)

$$Recall = \frac{True\_Positives}{True\_Positives + False\_Negatives}$$

F1-Score (Harmonic Mean of both)

$$F1 = 2 \times \frac{Precision \times Recall}{Precision + Recall}$$
